GPU Tetris

单机 GPU 任务队列 + nvidia-smi 风格监控。按利用率、显存与观察窗口，把多个训练安全地共置在同一张卡上；调度器崩溃，训练不停。

GitHub 源码与 README ↗

0调度器第三方运行时依赖
2每卡默认最多任务数
60s连续低利用率才补入
5+4队列策略 + 放置策略
适用范围适合单用户工作站或服务器，不是多租户集群调度器。仅运行同一用户的可信任务。
01

先玩一下：调度器是怎么想的

这是一个浏览器里的简化模拟（1 tick = 10 秒，约 0.6 秒演示一次）。提交几个任务，观察每张 GPU 的状态徽章如何在 OBSERVE → READY → HOLD / FULL 之间切换。

t = 0 tick
IDNAMETYPESTATUSGPUsDETAIL
阈值 util<65%观察 6 tick冷却 6 tick最低空闲显存 16 GiB每卡 ≤2Filler 阈值 <30% · 回收后 30 tick 再补入（演示压缩）

提示：先开启 Filler，等 GPU 被占卡任务占住，再提交“双卡独占”任务，可以看到占卡被回收、普通任务接手的全过程。

03

五分钟上手

  1. 初始化独立队列池

    池里有 SQLite 数据库、日志和调度锁，与源码完全分离。

  2. 自检

    doctor 检查池是否可写，以及 nvidia-smi 查询是否正常。

  3. 启动后台调度器

    重复执行不会启动第二个。也可用 run 前台运行并交给 systemd。

  4. 提交任务

    命令按 argv 直接执行，不隐式启动 shell；需要管道请显式 bash -lc '...'。

  5. 观察与查看日志

    --watch 2 每 2 秒刷新调度快照。

真实 GPU
tetris init
tetris doctor
tetris start
tetris submit --name experiment-1 --cwd /path/to/project -- python3 train.py --epochs 100
tetris-smi --watch 2
tetris logs JOB_ID -f --tail 50

没有 GPU？用模拟池演示

模拟池执行真实 CPU 子进程，CUDA_VISIBLE_DEVICES 为空。模式在 init 时固定，不要把它用于训练。

CPU 模拟
export TETRIS_POOL="$HOME/.local/state/gpu-tetris-demo"
tetris init --simulate
tetris config --set observation_seconds=0 --set launch_cooldown_seconds=0 --set poll_seconds=1
tetris start
tetris submit --name hello -- python3 -c 'print("hello queue")'
tetris-smi --watch 1
tetris stop
CAUTION只提交可信命令。任务参数、工作目录和日志可能含敏感数据，尽量不要通过命令行传递密钥。
04

默认调度规则

一个任务想进入某张卡，必须同时通过下列检查。READY 只表示资源条件满足，不是显存预留，也不保证某个具体任务马上派发。

10s采样间隔
<65%利用率连续 60 秒低于此值
60s补入后冷却并重新观察
16000最低空闲显存 MiB
≤2每卡任务上限
CLIsubmit / status
SQLite持久任务池
SchedulerGPU 监控 · 策略 · 派发
Worker独立监督进程
训练进程UUID 绑定 GPU

UUID 绑定

用 GPU UUID 写入 CUDA_VISIBLE_DEVICES，避免设备枚举顺序差异。

默认单用户模式

ownership_mode="single_user" 按整卡显存与利用率调度，不因队列外进程或 PID 映射失败而阻塞；任务数仅计本池。可选 strict 归属检查。

查询失败不盲发

nvidia-smi 查询失败时，调度器不会继续派发新任务。

依赖不阻塞他人

被依赖阻塞的任务不会挡住其余任务（strict_fifo 除外）。

05

命令速查

命令功能
tetris init初始化独立队列池（--simulate 为 CPU 模拟）
tetris start启动后台调度服务，重复调用不会启动第二个
tetris run前台运行，方便 systemd 托管
tetris stop停止调度服务；已运行任务继续执行
tetris submit -- PROGRAM ARG...提交任务，返回任务 ID
tetris-smi --watch 2每 2 秒显示调度快照，Ctrl+C 退出
tetris-smi --all包含已完成任务
tetris-smi --status failed只显示指定状态，可重复指定
tetris-smi --json版本化 JSON（schema v2），不含任务环境变量
tetris logs JOB_ID -f --tail 50跟随当前尝试日志；--raw 输出未清理的原始日志
tetris cancel JOB_ID取消等待任务，或请求 worker 终止运行任务（异步）
tetris retry JOB_ID手动重试失败或已取消的任务
tetris pause / resume暂停／恢复新任务派发，不停止运行中任务
tetris config [--set K=JSON]查看或修改调度配置
tetris doctor检查池与 NVIDIA 查询
tetris upgrade升级旧池 schema（需先停止调度器并排空任务）

任务选项

submit options
# 指定候选卡、最低空闲显存、环境变量
tetris submit --name train --gpus 0,1 --min-free-mb 24000 --env OMP_NUM_THREADS=4 -- python3 train.py
# 依赖：父任务成功后才运行
tetris submit --name evaluate --depends JOB_ID -- python3 evaluate.py
# 全局配置
tetris config --set per_gpu_limit=1 --set utilization_threshold=50 --set 'allowed_gpus=[0,1]'

任务状态：queued blocked starting running complete failed cancelled。退出码 0 才算完成；普通任务没有隐式自动重试。

NOTE--gpus 是候选卡白名单，不是卡数；卡数用 --gpu-count。
06

可组合的调度策略

queue_policy 决定“先给谁”，placement_policy 决定“放哪张卡”。两者独立，且都不会绕过利用率、观察窗口、冷却、显存与每卡上限检查。

队列策略

回填

按提交时间尝试；队首资源不足或依赖未满足时，后面的任务可以先跑。不是基于运行时间预估的 EASY backfill。

队首阻塞

队首无法启动时，后续任务一律不派发。缓解大任务饥饿，但会牺牲利用率。

老化

有效优先级 = priority + floor(等待秒数 / priority_aging_seconds)，默认每 300 秒加 1；同分按提交时间。

tetris submit --priority 10 -- python3 urgent_train.py

卡数少优先

按申请卡数从少到多，不是按预计运行时间。大任务可能长时间等待。

卡数多优先

按申请卡数从多到少，便于尽早处理大卡组。

放置策略

槽位少 → 利用率低 → 空闲显存多。均衡使用各张卡。

槽位多 → 满足要求的空闲显存较少。把共享任务集中起来，尽量留下整卡给多卡任务。

槽位少 → 空闲显存多 → 利用率低。尽量分散。

空闲显存多 → 槽位少 → 利用率低。优先放到显存最空的卡。

切换策略
tetris config --set 'queue_policy="priority"' --set 'placement_policy="pack"'
tetris config --set priority_aging_seconds=300

改配置只影响后续派发并重置观察窗口，不抢占在跑任务；不支持优先级抢占。

07

最低优先级占卡（Filler / Keeper）

Filler 是可回收的低优先级任务：卡闲时补入，普通任务需要资源时让路。可运行自己的程序，也可用内置 Keeper 预设产生计算负载；真实 GPU 上的 Keeper 需要 CUDA 版 PyTorch。

内置 Keeper
tetris keepers
tetris config --set filler_enabled=true
tetris submit --keeper floor --per-gpu --gpus 0,1 -- --util 40 --mem 512M

--per-gpu 必须明确指定 --gpus；Keeper 参数放在 -- 后。支持 steady、floor、wave、heartbeat、burn；--keeper-python /path/to/python 选择安装了 PyTorch 的解释器。参数在入队前校验；CPU 试跑可用 --backend none --max-seconds 30。

filler
tetris config --set filler_enabled=true --set filler_utilization_threshold=30
tetris submit --filler --name filler-0 --gpus 0 -- /你的环境/bin/python /你的程序/gpu_keeper.py
tetris submit --filler --name filler-1 --gpus 1 -- /你的环境/bin/python /你的程序/gpu_keeper.py
TIER

永远最低

所有队列策略下都排在普通任务之后；不参与老化，不允许 --priority，仅单卡 shared，每卡 ≤1。

ADMIT

更严格的准入

观察窗口内利用率必须始终严格低于 filler_utilization_threshold（默认 30%）。

REARM

回收后 30 分钟滞回

被调度器回收的卡，需再等 filler_rearm_seconds（默认 1800）才允许补入新的占卡。重启调度器后仍有效。

YIELD

协作式回收

普通任务无法启动时，调度器请求相关 filler 退出并重新排队；清理完成后才放行普通任务。

NOTE人工取消、正常退出、异常失败的 filler 都不会自动重启。占卡程序应可随时中断，且无必须保留的计算状态。
调整滞回
tetris config --set filler_rearm_seconds=600
08

单任务多卡

多卡任务全有或全无：只有所需卡同时满足条件，才在同一事务中认领整组；缺卡时零预留、零 attempt 增量。

multi-gpu
tetris submit --name ddp-4 --gpu-count 4 --gpus 0,1,2,3,4,5,6,7 --min-free-mb 24000 \
  -- torchrun --standalone --nnodes=1 --nproc-per-node=4 train.py
tetris submit --name shared-2 --gpu-count 2 --sharing shared -- python3 multi_gpu_program.py

默认独占

多卡默认 exclusive：每张卡必须没有本池任务。单卡默认 shared。

逻辑卡号

物理卡 2、5 在任务内映射为逻辑卡 0、1，不要在命令里再硬编码物理索引。

显存门槛按卡算

--min-free-mb 是每张卡的空闲显存，不是总和。

进程数自己管

调度器不会把脚本改造成 DDP。torchrun 的进程数需与 --gpu-count 一致，并用 --standalone 避免端口冲突。

LIMITS“独占”只是本池的逻辑独占，不是驱动锁或 cgroup 隔离；不支持 NVLink/NUMA 拓扑、MIG、多节点、弹性伸缩或硬显存预留。
09

读懂排队原因

任务排队时，状态表的 DETAIL 列会逐卡列出为什么这张卡不行。

DETAIL
Waiting for 2 eligible GPUs (exclusive, 24000 MiB per GPU):
  GPU0: HOLD >=65%;
  GPU1: LOW MEMORY 100<24000 MiB;
  GPU2: NOT EMPTY (1 tasks, exclusive needed);
  GPU3: READY
标记含义怎么办
READY该卡满足资源条件等待调度循环派发
OBSERVE / COOLDOWN观察窗口未满或冷却中等待，刚补入任务后会重置
HOLD >=65%当前利用率过高等待，或调高 utilization_threshold
LOW MEMORY空闲显存低于门槛降低 --min-free-mb 或等待释放
FULL / EXCLUSIVE达到每卡上限或被独占等任务结束，或调整 per_gpu_limit
UNKNOWN OWNER仅 strict 模式：GPU 进程无法匹配本池进程组确认来源；单用户环境可切回默认 ownership_mode="single_user"
PAUSED / DISABLED已 pause 或不在 allowed_gpustetris resume 或检查配置
进程归属模式
# 默认：单用户；保留整卡利用率、显存与本池任务数限制
tetris config --set 'ownership_mode="single_user"'
# 可选：严格阻塞无法匹配本池进程组的 GPU 进程
tetris config --set 'ownership_mode="strict"'
STALE如果状态表提示心跳过期（STALE），说明调度器没在运行，资源策略显示不是最新的——先 tetris start。
10

恢复、取消与安全边界

INDEPENDENT

Worker 独立于调度器

服务停止、SSH 退出或重启，都不会主动结束训练。

IDENTITY

进程身份校验

boot ID + PID 启动时钟，避免把复用的 PID 当成旧任务。

HANDSHAKE

启动握手

先持久化身份，再通过管道放行真正的训练命令。

NO-RERUN

缺凭据不重跑

没有退出凭据的尝试不自动重跑；worker 丢失时保留槽位，cancel 清理后再重试。

NOT A SANDBOX取消会清理进程组及带同一 attempt 标识的同用户子进程，必要时 SIGKILL。这不是 cgroup 沙箱：删除 TETRIS_ATTEMPT_TOKEN、脱离进程组或通过容器逃离监督的任务，无法保证清理完整。
  • 不提供 exactly-once 外部副作用保证。异常任务重试前，请检查已写入文件、外部服务和 checkpoint。
  • 池目录含数据库、日志、退出凭据，不要放到公开仓库、NFS 或不可信共享目录。
  • 不要在同一组 GPU 上同时运行多个池，也不要与其他调度器混用。
  • 升级：先停止调度器并排空任务，备份整个池，再 tetris upgrade，最后 tetris start。
