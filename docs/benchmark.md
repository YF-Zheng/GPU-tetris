# Benchmark 方案：动态共置 vs 独占式 FIFO

要回答的问题：在**相同 GPU、相同任务集合**下，tetris-smi 比“每卡一个任务的独占 FIFO”多完成多少有效训练？

## 对照组

| 组 | 配置 |
| --- | --- |
| A：独占 FIFO | `per_gpu_limit=1`，`queue_policy="fifo"` |
| B：动态共置（默认） | `per_gpu_limit=2`，`utilization_threshold=65`，`observation_seconds=60` |
| C：B + filler | 在 B 基础上 `filler_enabled=true`，并附带自己的 keeper 程序 |

## 工作负载

- 固定一个任务清单（至少 40 个）：混合小/中/大模型、不同显存占用和利用率；记录随机种子和命令。
- 每组使用同一批命令、同一提交顺序，一次性提交，并在所有任务结束后停止计时。
- 每组至少重复 3 次，报告中位数和范围。

## 指标

| 指标 | 来源 |
| --- | --- |
| Makespan（首个提交到最后完成） | `tetris-smi --json` 的提交/结束时间或自行记录 |
| 平均任务等待时间 | 提交时间到进入 `running` |
| GPU 平均利用率 / 显存占用 | `nvidia-smi dmon` 或 `--query-gpu` 每秒采样 |
| 单任务减速比 | 共置时的单任务墙钟 / 独占时的墙钟 |
| 失败与 OOM 数 | 任务状态与日志 |
| 有效吞吐 | 单位时间完成的 epoch / step / 样本数 |

## 判定与诚实说明

- 共置可能降低单任务速度；总吞吐提升才是目标，必须同时报告单任务减速比。
- 必须记录 OOM 次数，若共置导致失败要如实写入。
- 报告需包含 GPU 型号、驱动、CUDA、框架版本、任务清单和原始采样数据，便于他人复现。
